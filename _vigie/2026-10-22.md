## 1. PHP : deux vulnérabilités critiques sont maintenant corrigées

**Publication : 21 octobre 2026 · Statut : versions de sécurité publiées · Importance pratique : critique si PHP est présent dans une infrastructure exposée.**

Le préavis signalé hier est devenu un avis complet. Le projet PHP confirme que **CVE-2026-109618** et **CVE-2026-109619** peuvent permettre une exécution de code à distance sans authentification. Les versions corrigées sont :

- PHP **8.5.12**
- PHP **8.4.27**
- PHP **8.3.36**
- PHP **8.2.35**

Le projet indique qu’aucune mesure d’atténuation ne constitue une solution complète : la mise à jour est le seul choix considéré sûr. PHP 8.1 et les branches plus anciennes ne reçoivent plus de versions régulières du projet. Des fournisseurs de distributions ou de soutien à long terme peuvent toutefois offrir des correctifs rétroportés; le projet a aussi publié des correctifs sources minimaux pour PHP 7.4, 8.0 et 8.1 afin d’aider les environnements qui doivent encore les compiler.

**Source primaire :** [PHP — archive officielle et avis du 21 octobre 2026](https://www.php.net/archive/2026.php).

### Pourquoi c’est pertinent

Cette vulnérabilité n’est pas annoncée dans MapServer, GDAL ou pygeoapi. Elle devient néanmoins pertinente pour une plateforme géospatiale si PHP est installé dans une image, utilisé par une application Web voisine ou nécessaire à un déploiement de PHP MapScript.

La priorité est donc de vérifier l’exposition réelle plutôt que de supposer que toute la chaîne géospatiale est touchée.

### Action recommandée

1. Inventorier PHP sur les hôtes, dans les conteneurs et dans les images de déploiement, par exemple avec `php -v` et le gestionnaire de paquets approprié.
2. Mettre à jour vers une version corrigée ou appliquer le correctif fourni par le distributeur/LTS.
3. Reconstruire et redéployer les images concernées; une mise à jour de l’hôte ne corrige pas automatiquement une bibliothèque embarquée dans un conteneur.
4. Si une mise à jour immédiate est impossible, consulter les mesures temporaires de l’avis officiel, tout en les traitant comme des réductions d’exposition et non comme des correctifs complets.

Aucune action n’est nécessaire pour les services dont l’inventaire confirme l’absence de PHP.
