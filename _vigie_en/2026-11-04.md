## 1. GDAL merges the fix for the Windows thread race

**Merged: November 3, 2026 at 09:16 EST · Status: fix merged into `master`, not yet released · Practical importance: medium and conditional for raster processing on Windows.**

The problem reported on October 30 is no longer accompanied only by a proposed patch: the fix has now been integrated into GDAL. On Windows, a thread created by `CPLCreateJoinableThread()` could finish before its handle was recorded. The code could then treat it as detached and free its internal structure before a second free occurred in `CPLJoinThread()`.

The change adds an explicit `bJoinable` flag, set before thread creation, so that only a genuinely detached thread frees that structure itself. The documented case combined multiple Python processes with `gdal.Warp(..., multithread=True)`. According to the fix analysis, the pthread path used on Linux is not affected.

**Why it matters:** raster pipelines can combine process-level parallelism with GDAL’s internal multithreading. On Windows workstations or batch processing systems, that combination could terminate the process instead of producing a recoverable GDAL error. This fix does not justify a general change to Linux services.

**Action: test and monitor.** Keep a Windows stress test that covers multiple processes and `gdal.Warp(multithread=True)`. If this scenario is used, wait for a GDAL release containing the commit before treating the issue as fixed in distributed environments; merged source code alone does not change existing installations.
