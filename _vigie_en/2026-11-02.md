## 1. pygeoapi normalizes the CoverageJSON media type in EDR responses and UI

**Merged: November 1, 2026 · Status: change merged into `master`, not yet published in a new release · Practical importance: high for pygeoapi, EDR and Coverages integrations.**

pygeoapi replaces `application/prs.coverage+json` with the normalized `application/vnd.cov+json` media type in coverage response `Content-Type` headers, collection links and JSON-link detection in the HTML template. The pull request ties this choice to Clause 10 of OGC specification 21-069r2. It also confirms successful negotiation for a request using `Accept: application/vnd.cov+json`.

This change extends the use of `application/vnd.cov+json` already present in some EDR links in pygeoapi 0.24.0; it is not yet a new release. Its main effect is to remove an inconsistency among metadata, response headers and the HTML interface.

**Why it matters:** GeoMet clients and other OGC API consumers that strictly validate `Content-Type`, negotiate formats with `Accept`, index links by media type, or use that field in caches and contract tests may observe a change after a future pygeoapi upgrade.

**Action: test and prepare.** Add a test using `Accept: application/vnd.cov+json`, update assertions that still expect `application/prs.coverage+json`, and temporarily accept both values client-side if a transition period is needed. Wait for a published pygeoapi version before treating this behavior as available in a stable distribution.

**Primary sources:** [geopython/pygeoapi — pull request #2477](https://github.com/geopython/pygeoapi/pull/2477) · [OGC 21-069r2, Clause 10](https://docs.ogc.org/cs/21-069r2/21-069r2.html#_b8b17e78-0147-4b58-8ade-a19465b57abc) · [pygeoapi 0.24.0](https://github.com/geopython/pygeoapi/releases/tag/0.24.0).

## 2. GDAL guards its SWIG typemaps against cleanup on null pointers

**Merged: November 1, 2026 at 21:11 EST (November 2 at 02:11 UTC) · Status: change merged into `master`, not yet released · Practical importance: medium and conditional.**

GDAL added null-pointer checks to the `freearg` typemaps in its Python and Java bindings. The change responds to a recent modification in SWIG `master`: when conversion of an earlier argument fails, cleanup may now run before some later arguments have been initialized. Without a guard, a GDAL typemap could dereference a null pointer and crash. The maintainers state that current SWIG versions are not affected and that the guards remain compatible with them.

**Why it matters:** the impact is in the build supply chain rather than in raster or vector processing itself. An image or package built directly against SWIG `master` could encounter the problem during an invalid Python call; the source does not show that current released GDAL binaries are affected.

**Action: monitor; test only for bleeding-edge builds.** If a CI chain builds GDAL against SWIG `master`, use a GDAL commit containing the fix or temporarily pin SWIG, then add negative argument-conversion tests. No production change is warranted for stable distributions based on this merge alone; wait for a GDAL release that includes it.

**Primary sources:** [OSGeo/GDAL — pull request #15463](https://github.com/OSGeo/gdal/pull/15463) · [SWIG — argument-cleanup change](https://github.com/swig/swig/commit/f8cf11b7209c03c5154ffb738f1650c2631027c3).
