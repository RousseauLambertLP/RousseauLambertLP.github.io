## 1. MCP formalizes severe-incident escalation under CRA stewardship

**Date:** November 13, 2026  
**Status:** policy merged into the specification repository; no normative protocol change and no vulnerability announced  
**Practical importance:** medium for agent-tool governance and software supply chains

The Model Context Protocol project added an emergency mechanism to its security policy for actively exploited vulnerabilities and severe incidents, including compromise of the release process. External reports must use a private GitHub Security Advisory on the affected repository. Core maintainers then coordinate with the Linux Foundation CRA steward; the documentation notes regulatory windows of 24 hours for an early warning and 72 hours for a fuller notification. SDK repositories with their own `SECURITY.md` were not changed by this commit.

**Why this matters to practitioners:** an MCP server exposing weather or geospatial APIs adds another surface to the trust chain. If an official component has an exploited vulnerability or a release compromise, the reporting and escalation path is now explicit, making it easier to include MCP in incident-response and dependency-management plans.

**Possible action:** monitor. Reference the official policy in incident-response procedures covering MCP, and use a private advisory rather than a public issue for a sensitive report. This documentation change alone requires no protocol or SDK update.
